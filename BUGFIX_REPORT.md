## 🔴 CRITICAL SECURITY FIXES

### 1. ✅ Path Traversal via sanitize_filename (CWE-22)
**File:** `scripts/utils.sh`  
**Risk:** HIGH — The `sanitize_filename()` function did not strip `/` characters, allowing a malicious stream title containing `/` to cause directory traversal or unexpected file writes.  
**Fix:** Added `/` to the removal regex. Also added `.` and `..` stripping for defense-in-depth.

### 2. ✅ Secret Leakage in Logs
**File:** `scripts/utils.sh`  
**Risk:** HIGH — `set_env()` and `set_output()` logged full variable values (`log_debug "Env: SECRET_KEY=abc123"`) — a DEBUG=true run would expose all secrets including API keys, MEGA passwords, and GitHub PATs in plaintext logs.  
**Fix:** Changed to `log_debug "Env: SECRET_KEY=<set>"` — only variable name logged, never value.

### 3. ✅ @everyone Notification Spam
**File:** `scripts/discord-notify.sh`  
**Risk:** MEDIUM — EVERY notification (including routine "recording complete") pinged @everyone, causing channel fatigue and desensitizing users to actual emergencies.  
**Fix:** @everyone now only fires for `alerts` channel (live detection + failures). Recording-complete notifications are informative-only, no ping.

### 4. ✅ MEGA Credentials in Predictable Temp Files
**Files:** `scripts/upload-clouds.sh`  
**Risk:** HIGH — MEGA email/password were written to `/tmp/.megarc` and `/tmp/.megarc_thumb` — fully predictable paths, world-readable on a multi-tenant GitHub Actions runner.  
**Fix:** Now uses `mktemp /tmp/megarc_XXXX` to create securely-randomized temp files.

### 5. ✅ Cloud Account CSVs Not in .gitignore
**File:** `.gitignore`  
**Risk:** CRITICAL — `scripts/mega/accounts.csv` and `scripts/pixeldrain/accounts.csv` contain plaintext email/password pairs and API keys, committed to a PUBLIC repository. The .gitignore had a misleading comment saying they were "intentionally tracked" but no actual ignore rule.  
**Fix:** Added proper `.gitignore` entries for all account CSV files, signin results, and old account backups.

### 6. ✅ Debug Logging of API Keys
**File:** `scripts/upload-clouds.sh`  
**Risk:** MEDIUM — Gofile API endpoint URLs and Pixeldrain API key presence were logged in debug output.  
**Fix:** Endpoints truncated, API key status changed from showing `SET` to boolean `yes/no`.

## 🔴 CRITICAL BUG FIXES

### 7. ✅ AV1 Codec Not Detected
**File:** `scripts/post-process.sh`  
**Risk:** HIGH — Only VP8/VP9 were checked for browser-incompatible codecs. AV1 has the same issues (poor browser support in MP4 containers) but was silently skipped, producing files that wouldn't play inline.  
**Fix:** Added `|| [[ "$vcodec" == "av1" ]]` to the codec detection gate.

### 8. ✅ Variable Shadowing in VP9 Transcode
**File:** `scripts/post-process.sh`  
**Risk:** MEDIUM — The `encode_start` variable was reused inside the VP9->H264 transcode block, shadowing the parent function's `encode_start`. This caused incorrect timing reports.  
**Fix:** Renamed to `encode_start_h264`.

### 9. ✅ Thumbnail Resolution Threshold Too Aggressive
**File:** `scripts/utils.sh`  
**Risk:** MEDIUM — The `content_length > 5000` check rejected perfectly valid thumbnails that YouTube served as 3-4KB (e.g., lower-res thumbnails on live streams).  
**Fix:** Lowered threshold to 2000 bytes (placing it between the ~1.2KB gray placeholder and real thumbnails).

### 10. ✅ Fragile json_escape Fallback
**File:** `scripts/utils.sh`  
**Risk:** MEDIUM — The sed-based fallback for JSON escaping was fragile and error-prone with complex characters, plus it was doubled creating duplicate code paths.  
**Fix:** Simplified to pure Python3 approach with a clean printable-only fallback.

### 11. ✅ Discord API Rate Limiting
**File:** `scripts/discord-notify.sh`  
**Risk:** MEDIUM — No rate limiting between sequential webhook calls could trigger Discord's 5-requests-per-second rate limit, causing notifications to be dropped.  
**Fix:** Added `_discord_rate_limit()` guard with 1-second minimum spacing between calls.

### 12. ✅ Archive.org Metadata — Meaningless Titles
**File:** `scripts/upload-clouds.sh`  
**Risk:** LOW — Uploaded files were tagged as "Personal Media Backup" by "Media Archive Bot" — completely uninformative for anyone browsing Archive.org.  
**Fix:** Changed to "The Muslim Lantern Live Stream Recording" by "The Muslim Lantern" with descriptive summary.

## 🟡 MODERATE IMPROVEMENTS

### 12. ✅ FORCE_RECORD Cookie Warning Suppression
**File:** `scripts/check-cookies.sh`  
**Risk:** LOW — Cookie health alerts would fire during FORCE_RECORD mode even though cookies aren't needed for VOD recording.  
**Fix:** `FORCE_RECORD=true` now suppresses cookie warnings alongside `PUBLIC_STREAM_ONLY=true`.

### 13. ✅ Gofile Alive Check Reliability
**File:** `scripts/repair-mirrors.sh`  
**Risk:** LOW — The "alive" check for Gofile links only checked page byte size (< 500 bytes = dead), which is unreliable and flagged legitimate small pages as dead.  
**Fix:** Added content-based checking for known Gofile error messages ("file was deleted", "expired", "404", etc.) with size threshold lowered to 300 bytes.

### 14. ✅ MEGA Rotation Timeout
**File:** `scripts/upload-clouds.sh`  
**Risk:** LOW — MEGA account rotation could hang indefinitely on unhealthy accounts.  
**Fix:** Added `timeout 60` guard around `select_mega_account()`.

## 🔒 REMAINING ARCHITECTURAL NOTES

1. **Plaintext passwords still in committed git history** — The accounts.csv files are still in the git history even if newly committed files are ignored. Run `git filter-branch` or use GitHub support to purge them from all history.
2. **Multi-tenant runner risk** — MEGA passwords still appear briefly in process lists when running `megatools` (visible to other processes on shared runners). Consider using a secrets vault service.
3. **YouTube cookies in workflow logs** — The `YOUTUBE_COOKIES` secret is base64-decoded then written to `cookies.txt`. If workflow debug logging is enabled, this file content could be exposed in step output.
